## 1. 포지셔닝
- **한 줄:** "바이브코딩으로 만든 서비스, 결제까지 바이브로."
- **카테고리:** 바이브코더/1인 개발자/비사업자를 위한 결제 연동 + PG 심사 지원 솔루션
- **약속:** 코드 몇 줄로 결제 연동, 까다로운 PG 심사 준비를 도와주고, 사업자가 아니어도 시작할 수 있는 길을 제시

## 2. 타깃 시청자 (페르소나)
| 페르소나 | 상황 | 핵심 고충 |
|---|---|---|
| A. 바이브코더 직장인 | Cursor·Claude Code 등으로 사이드 프로젝트 완성 | "만들긴 했는데 돈 받는 법을 모르겠다" |
| B. 비사업자 크리에이터 | 강의·템플릿·전자책 판매 희망 | 사업자등록·통신판매업 신고 부담, PG 계약 거절 |
| C. 초기 1인 창업자 | MVP 출시 직전 | PG 심사 반려, 필수 고지사항 누락, 정산 지연 |
| D. 비개발 기획자 | 노코드/AI로 앱 제작 | API 키·웹훅·결제 검증 개념이 어려움 |

## 3. 고충 리서치 맵 (콘텐츠 기둥)
1. **결제 연동의 기술 장벽** — SDK/API 문서 난이도, 테스트키↔라이브키, 웹훅, 결제 금액 서버 검증, 환불/취소 API, 정기결제(빌링키)
2. **PG 심사의 벽** — 사이트 필수 표기(상호·대표자·사업자번호·통신판매업 번호·주소·연락처), 이용약관·개인정보처리방침·환불정책, 실제 상품/가격 페이지, 업종 제한, 심사 기간·반려 사유
3. **비사업자/개인의 장벽** — 개인은 PG 직접 계약이 어려운 현실, 사업자등록·통신판매업 신고 절차, 간이과세 vs 일반과세, 언제 사업자를 내야 하나
4. **수익화 이후** — 정산 주기, 수수료 구조, 세금계산서/현금영수증, 차지백·분쟁
